  • 直觉：让 RM 学会给"好回答"打高分、给"差回答"打低分
  • 开始阅读 Hugging Face RLHF 课程：https://huggingface.co/learn/rlhf-course/unit0/introduction

周五（2h）：PPO 在 LLM 中的四模型架构

  • 画出 RLHF-PPO 的完整数据流图：
    • Actor（策略 LLM）：生成回答
    • Critic（价值模型）：估计状态价值，用于计算 advantage
    • RM（奖励模型）：对回答打分
    • Ref（参考模型）：计算 KL 散度，防止策略偏离太远
  • 理解训练循环：采样 prompt → Actor 生成 → RM 打分 → 算 advantage → 更新 Actor & Critic
  • 思考：为什么需要 4 个模型？每个能不能省掉？

第 11 周：DPO 训练 + 离线对齐方法族

本周目标

每日任务

周一（2h）：DPO 论文精读

  • 论文：Rafailov et al. 2023，https://arxiv.org/abs/2305.18290
  • 核心推导：将 RM + PPO 两步合并为一步，直接从偏好数据优化策略
  • DPO loss = -log σ(β · (log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)))
  • 关键 insight：最优策略和最优 RM 之间存在解析解关系，所以可以绕过 RM

周二（2h）：DPO 实战——用 TRL 跑 DPO 训练

周三（2h）：DPO 调参 + 用 LLaMA-Factory 跑 DPO

周四（2h）：DPO 变体概览 + RLVR 反思

  • 快速了解 DPO 变体的核心改进思路：
    • KTO（Kahneman-Tversky Optimization）：不需要成对偏好数据，只需要 thumbs-up/down
    • ORPO（Odds Ratio Preference Optimization）：将 SFT 和对齐合并为一步
    • SimPO（Simple Preference Optimization）：去掉 reference model，更简洁
  • 精读 "RLVR 并不如想象中那么有效"：https://arxiv.org/abs/2504.02532
    • 理解对 RLVR（RL with Verifiable Rewards）范式的质疑

周五+周末（6-8h）：DPO vs PPO vs GRPO 系统对比 + 总结

    • 训练复杂度（代码量、调参难度）
    • 资源需求（显存、训练时间）
    • 最终效果
  • 理解各自适用场景：
    • DPO：有离线偏好数据、资源有限时首选
    • PPO：经典 RLHF，需要 RM，适合通用对齐
    • GRPO：有可验证 reward 的场景（数学、代码），效果最强
  • 写一篇对比文章："RLHF vs DPO vs GRPO：如何选择后训练算法"

第 17 周：分布式训练基础

本周目标

每日任务

周一（2h）：三种并行策略的原理

  • Data Parallel（DP）：数据分片，模型复制 → 简单但显存浪费
  • Tensor Parallel（TP）：模型层内切分 → 减少单卡显存但通信多
  • Pipeline Parallel（PP）：模型层间切分 → 适合超大模型
  • 画三种策略的示意图，标记数据流和通信模式

周二（2h）：PyTorch FSDP

  • 精读 FSDP 论文：https://arxiv.org/abs/2304.11277
  • FSDP = 将 DP + 参数分片结合，每张卡只保存模型的一部分参数
  • 跑 PyTorch 官方 FSDP Tutorial：https://pytorch.org/tutorials/intermediate/FSDP_tutorial.html
  • 在 2 张 GPU 上用 FSDP 微调 Qwen2.5-3B

周三（2h）：DeepSpeed ZeRO 概览

  • 精读 ZeRO 论文 Section 3-5：https://arxiv.org/abs/1910.02054
  • ZeRO-1/2/3 分别分片什么（optimizer states / gradients / parameters）
  • 阅读 DeepSpeed ZeRO 教程：https://www.deepspeed.ai/tutorials/zero/
  • 对比 FSDP 和 DeepSpeed ZeRO-3 的异同

周四（2h）：FSDP2 新特性

  • veRL 推荐使用 FSDP2
  • 理解 FSDP2 相比 FSDP1 的改进（更好的吞吐量和显存，可与 torch.compile 组合）
