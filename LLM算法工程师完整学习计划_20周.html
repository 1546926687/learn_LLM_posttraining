第 4 周：7B 模型微调实战

本周目标

每日任务

周一（3h）：数据工程基础——清洗、过滤、质量打分

  • 从 HuggingFace 下载 Qwen2.5-7B-Instruct：https://huggingface.co/Qwen/Qwen2.5-7B-Instruct
  • 下载 Alpaca-GPT4 数据集：https://huggingface.co/datasets/vicgalle/alpaca-gpt4
  • 数据清洗 pipeline（这是工业界的核心技能，比调参更重要）：
    1. 去重：用 MinHash 或精确去重去掉重复/近似重复的条目
    2. 长度过滤：去掉 output 过短（< 20 字）或过长（> 2048 字）的条目
    3. 质量打分：用规则（是否有完整句子、是否包含乱码）+ 简单模型（perplexity 过滤）给数据打分
    4. 类型标注：对每条数据标注任务类型（翻译/摘要/QA/代码/创作/推理）
  • 阅读 Self-Instruct 论文 Section 2-3：https://arxiv.org/abs/2212.10560
    • 了解如何用 LLM 生成高质量训练数据

    • quantization_bit: 4（NF4 量化，参考 QLoRA 论文：https://arxiv.org/abs/2305.14314）
    • lora_rank: 16, lora_alpha: 32, lora_target: all
    • learning_rate: 2e-4, num_train_epochs: 3, cutoff_len: 2048
    • per_device_train_batch_size: 2, gradient_accumulation_steps: 4
  • 开启 wandb 监控：export WANDB_PROJECT=qwen7b-sft

周三（2h）：监控训练与问题排查

    • loss 是否在前 100 步内开始下降？如果不降 → 检查 lr 是否太小或数据格式是否正确
    • loss 下降后是否反弹？→ 可能 lr 太大或数据有噪声

    • 方法 3：开启 gradient_checkpointing: true（参考论文：https://arxiv.org/abs/1604.06174）

第 5 周：深入理解训练细节

每日任务

周一（2h）：SFT loss mask 原理

  • 阅读 HuggingFace Transformers 中 DataCollatorForSeq2Seq 的源码：https://github.com/huggingface/transformers/blob/main/src/transformers/data/data_collator.py
  • 核心机制：只对 response 部分算 loss，instruction/input 部分的 label 设为 -100
  • PyTorch 的 CrossEntropyLoss(ignore_index=-100) 会自动跳过 -100 位置
  • 动手实验：在 LLaMA-Factory（https://github.com/hiyouga/LLaMA-Factory）中分别用 train_on_prompt: true 和 train_on_prompt: false 训练，对比 loss 曲线和最终效果
    • 预期：train_on_prompt: false（只对 response 算 loss）效果更好
  • 阅读参考博客：Hugging Face "How to fine-tune LLMs" https://huggingface.co/blog/sft-trainer

  • 阅读 Spinning Up 的 VPG (Vanilla Policy Gradient) 文档：https://spinningup.openai.com/en/latest/algorithms/vpg.html
  • 理解 Value Function（价值函数）：
    • V(s)：从状态 s 出发，遵循策略 π 的期望回报
    • Critic 就是用来估计 V(s) 的网络
  • 理解 GAE（Generalized Advantage Estimation）：
    • TD(0) 到 TD(λ) 的过渡：在偏差和方差之间权衡
    • GAE 公式：A_t^GAE = ∑ (γλ)^l · δ_{t+l}，其中 δ_t = r_t + γV(s_{t+1}) - V(s_t)
    • 直觉：λ=0 → 高偏差低方差（只看一步）；λ=1 → 低偏差高方差（看到结束）
  • 这是理解 PPO 的关键前置知识

第 11 周：DPO 训练 + 离线对齐方法族

本周目标

掌握 DPO 的原理和实操，手写 DPO 训练循环加深底层理解，掌握合成偏好数据的构造方法。

每日任务

周一（3h）：DPO 论文精读

  • 论文：Rafailov et al. 2023，https://arxiv.org/abs/2305.18290
  • 核心推导（需要手写一遍）：
    • 从 RM + PPO 的目标函数出发，推导出最优策略的解析解
    • 将最优策略代入 Bradley-Terry 模型，得到 DPO loss
    • DPO loss = -log σ(β · (log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)))
  • 关键 insight：最优策略和最优 RM 之间存在解析解关系，所以可以绕过 RM
  • 与上周的 RL 知识对接：DPO 是 off-policy 方法，不需要在线采样

周二（3h）：手写 DPO 训练循环（关键！）

  • ⚠️ 不用 TRL 或 LLaMA-Factory，用原生 PyTorch 实现简化版 DPO 训练（~80 行）：
    # 伪代码框架
for batch in dataloader:
    # 1. 计算 policy model 在 chosen/rejected 上的 log prob
    chosen_logps = get_logprobs(model, batch["chosen"])
    rejected_logps = get_logprobs(model, batch["rejected"])
    # 2. 计算 reference model 的 log prob（with torch.no_grad()）
    ref_chosen_logps = get_logprobs(ref_model, batch["chosen"])
    ref_rejected_logps = get_logprobs(ref_model, batch["rejected"])
    # 3. 计算 DPO loss
    logits = beta * ((chosen_logps - ref_chosen_logps) - (rejected_logps - ref_rejected_logps))
    loss = -F.logsigmoid(logits).mean()
    loss.backward(); optimizer.step()
  • 关键细节：get_logprobs 怎么写？→ 逐 token 取 log_softmax 后 gather，再 sum
  • 在 Qwen2.5-0.5B + HH-RLHF 小子集上验证你的实现能训起来
  • 为什么要做这一步：面试时被问到 "DPO loss 具体怎么算的"，你需要答到代码级
  • 产出：一个独立可运行的 dpo_train.py 脚本

周三（3h）：用 TRL / LLaMA-Factory 跑 DPO + 合成偏好数据

  • 用 TRL 的 DPOTrainer 在 Qwen2.5-1.5B 上训练，对比你手写版本的结果：
    • 参考 TRL 示例脚本：https://github.com/huggingface/trl/tree/main/examples
    • LLaMA-Factory 也支持 stage: dpo，对比两种框架的体验
  • 构造合成偏好数据（工业界核心技能）：
    • 用你的 SFT 模型对同一个 prompt 生成 5 个回答（temperature=0.7）
    • 用更强的模型（如 GPT-4 API 或 Qwen2.5-72B API）做 judge，选出 best 和 worst
    • 构造 (prompt, chosen, rejected) 三元组，共 500 条
    • 这就是 拒绝采样（Rejection Sampling） 的核心思想，也是 DeepSeek-R1 pipeline 的关键步骤
  • 产出：500 条合成偏好数据 + DPO 训练结果

周四（2h）：DPO 变体概览 + RLVR 反思

  • 快速了解 DPO 变体的核心改进思路：
    • KTO（Kahneman-Tversky Optimization）：不需要成对偏好数据，只需要 thumbs-up/down。论文：https://arxiv.org/abs/2402.01306
    • ORPO（Odds Ratio Preference Optimization）：将 SFT 和对齐合并为一步。论文：https://arxiv.org/abs/2403.07691
    • SimPO（Simple Preference Optimization）：去掉 reference model，更简洁。论文：https://arxiv.org/abs/2405.14734
  • 精读 "RLVR 并不如想象中那么有效"：https://arxiv.org/abs/2504.02532
    • 理解对 RLVR（RL with Verifiable Rewards）范式的质疑

周五+周末（6-8h）：DPO vs PPO vs GRPO 系统对比

  • 在同一数据集和模型上做三方对比（用 benchmark 分数，不要只用主观评价）：
    • 训练复杂度（代码量、调参难度）
    • 资源需求（显存、训练时间）
    • lm-evaluation-harness 评测分数
  • 理解各自适用场景：
    • DPO：有离线偏好数据、资源有限时首选
    • PPO：经典 RLHF，需要 RM，适合通用对齐
    • GRPO：有可验证 reward 的场景（数学、代码），效果最强
  • 产出：三方对比表格（含 benchmark 数据）

第 14 周：模型量化

本周目标

每日任务

周一（2h）：量化基础概念

  • 阅读 Lilian Weng 博客中的量化章节：https://lilianweng.github.io/posts/2023-01-10-inference-optimization/#quantization
  • 阅读 HuggingFace 量化指南：https://huggingface.co/docs/transformers/main/en/quantization/overview
  • 理解数据类型层级：FP32（32bit）→ FP16/BF16（16bit）→ INT8（8bit）→ INT4（4bit）
    • 每降一级：显存约减半、速度约提升 1.5-2x、但精度可能下降
  • 两种主流量化方式：
    • PTQ（Post-Training Quantization）：训练后量化，不需要重新训练，直接量化权重
    • QAT（Quantization-Aware Training）：训练时模拟量化误差，精度更好但需要训练
  • 理解关键概念：absmax 量化、zero-point 量化、对称 vs 非对称量化
  • 产出：一份量化基础概念笔记（数据类型对比表 + PTQ vs QAT 对比）

  • 精读 GPTQ 论文核心思想：https://arxiv.org/abs/2210.17323

周三（2h）：AWQ 量化实操

  • 精读 AWQ 论文核心思想：https://arxiv.org/abs/2306.00978
    • 核心：保护重要权重通道（基于激活分布识别），牺牲不重要的
  • 用 AutoAWQ（https://github.com/casper-hansen/AutoAWQ）做 AWQ 量化
  • 对比 GPTQ 的效果差异

周四（2h）：量化对模型质量的影响

  • 思考：量化对不同任务类型（数学推理 vs 知识问答 vs 代码）的影响是否一致？

周五+周末（6-8h）：量化实验报告

周四（2h）：偏好数据质量控制

  • 偏好数据（chosen/rejected）的质量直接决定 DPO/PPO 的效果
  • 质量控制方法：
    • 标注者一致性：同一条数据让 3 个标注者（或 3 个 LLM Judge）独立标注，计算一致性（Fleiss' kappa）
    • 难度分层：easy pairs（差距明显）vs hard pairs（差距微妙）→ hard pairs 更有训练价值
    • 去噪：过滤掉标注不一致（chosen 和 rejected 差距不明显）的数据

    6. vLLM 的 PagedAttention 原理

    • 类比操作系统虚拟内存：逻辑块 → 物理块映射
    • 解决的问题：KV Cache 内存碎片 → 提高吞吐量
    • 参考论文：https://arxiv.org/abs/2309.06180

    7. 分布式训练中 FSDP 和 TP 的区别

    • FSDP：参数分片到多卡，需要时 all-gather 恢复（参考：https://arxiv.org/abs/2304.11277）
    • TP：将单个层内的计算切分到多卡（参考 Megatron-LM：https://arxiv.org/abs/1909.08053）
    • 适用场景：FSDP 适合研究原型、TP 适合极致性能

    8. 如何设计模型评测方案

    • 三层评测体系（第 15 周构建的）：Benchmark → LLM-as-Judge → Badcase 分析
    • 各层的作用：粗筛 → 细评 → 定位改进方向
    • 常用 Benchmark：MMLU / GSM8K / HumanEval / IFEval（每个评测什么能力）

    9. 训练中 loss 不下降怎么排查

    • 排查清单（按优先级）：
      1. 数据格式是否正确（label 是否被正确设置）
      2. learning rate 是否合理（太大 → loss 震荡；太小 → 不下降）
      3. 模型是否被正确加载（权重是否被冻结）
      4. 梯度是否正常（检查 grad_norm，是否为 0 或 NaN）
      5. 数据是否有问题（随机看 10 条 tokenize 后的数据）

    10. Reward Hacking 是什么、怎么防止

    • 定义：模型学会 "骗" RM 的高分策略，但实际回答质量下降
    • 原因：RM 不完美，存在可被 exploit 的漏洞
    • 防止方法：KL 惩罚（限制策略偏离 reference 的幅度）、定期更新 RM、多 RM 投票
    • 参考论文：https://arxiv.org/abs/2210.10760
